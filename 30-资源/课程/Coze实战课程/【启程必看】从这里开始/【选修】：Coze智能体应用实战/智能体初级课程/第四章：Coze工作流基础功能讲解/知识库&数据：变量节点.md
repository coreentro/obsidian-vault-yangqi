# 什么是变量？

很多学Coze的小伙伴会问：变量是不是一个编程概念？

确实，变量是编程中的基本概念，而Coze中的变量节点也和编程中的变量概念类似。

但变量并不是编程独有，在数学、统计等多个领域都有变量的概念。

## 最简单的理解

变量是数据的载体，它有两个核心作用：

<callout emoji="💡">
1. **存储数据**：将数据存储在变量中，**使数据有一个名字标识**，可以随时访问和修改。
2. **引用数据**：通过变量名来来使用存储的数据，从而在不同的地方或不同的时间点进行数据传递和操作。
</callout>

想象你有一个**带标签的盒子**：

- 盒子可以用来存放东西（**存放的东西就是数据**）
- 标签是盒子的名字（**这个标签就是变量名**）
- 你可以随时往盒子里放东西，也可以随时拿出来使用（**从盒子里取东西的过程就是使用变量的数据**）

## 数学中的变量

让我们看一个简单的数学方程：

```Plain Text
y = 2x + 3
```

在这个方程中：

- x 是一个可以变化的数字
- 当 x = 1 时，y = 5
- 当 x = 2 时，y = 7
- x 可以是任何数字

**数学中的变量特点**：代表未知数或可变的数值

## 编程中的变量

编程中的变量则更像是我们前面说的**带标签的盒子**：

```Python
name = "小明"     # 存储名字
age = 18        # 存储年龄
score = 95       # 存储分数
```

**编程中的变量特点**：

- **是一个存储数据的容器**
- 可以随时更改里面存储的值
- 可以存储各种类型的数据（文字、数字、列表等）

## 生活中的例子

让我们用一个简单的例子来理解：

小明要给小红传递考试答案，这个过程是这样的：

1. 小明拿了一张纸条（创建了一个名字叫做答案的变量）
2. 在纸条上写下答案"ABCD"（给变量赋值）
3. 小红看到纸条上的答案（使用变量的值）

用代码来表示就是：

```Python
# 1. 创建变量并存入答案
answer = "ABCD"  

# 2. 使用变量中的答案
print(f"答案是: {answer}")
```

# Coze中的变量节点

让我们再来看那个经典的AI Agent公式

<callout emoji="💡">
**智能体 = LLM（大模型）+ Planning（规划）+ Memory（记忆）+ Tools（工具）**
</callout>

变量节点则是使用利用外部存储来解决AI Agent中的Memory问题：

在Coze工作流中，变量节点更接近于编程中的变量概念：

- 可以存储用户输入的内容
- 可以存储中间计算的结果
- 可以在工作流的不同节点之间传递数据

## 变量的两个核心要素

1. **名字**：变量的标识符，用来引用变量
2. **值**：变量中存储的具体内容

## 变量的两个核心操作

1. 给变量赋值：将某一个具体的值设置到一个具体的变量中
2. 从变量中取值：获取这个变量中存储的数据，给其他节点使用

## 变量的作用范围

**变量并不属于某个工作流，而是属于整个智能体或者AI应用。**

**所以在Coze中创建变量的时候并不是在工作流中创建的，而是在智能体中创建的**

**而在工作流中只是通过变量节点用来设置变量的值或者获取变量的值**

## 变量的类型

Coze中的变量有三种类型：

用户变量：

<callout emoji="💡">
用户变量用于存储每个用户在使用应用过程中，需要持久化存储和读取的数据，例如用户的个性化设置、语言偏好、历史交互记录等。
这里注意两个点：
1. 变量是永久存储的，也就是说如果你设置了值，不清除的话，他会一直存在
2. 变量是用户间隔离的，每个用户有自己独立的变量值
</callout>

系统变量：

<callout emoji="💡">
> 系统默认创建用户信息、飞书等类别的系统变量，你不可以新增、修改、删除默认的系统变量。
> 
> 这些系统变量默认全部关闭，为不可用状态，你可以根据实际业务需求选择开启需要的系统变量。
> 
> 开启后，系统在用户请求时自动产生变量数据，**这些数据是只读的，但不可由用户或开发者修改**。
> 
> 通过工作流节点例如问答、结束等节点可以获取系统变量值，**变量名称必须与应用中设置的变量名称一致**。
总结一下：系统变量是Coze自身提供的内容，不需要用户单独设置，而且不允许修改其中的内容，只允许读取内容
</callout>

应用变量：

<callout emoji="💡">
首先注意：在目前为止，应用变量不能在智能体中使用，只能在AI应用中使用（我们后面讲到）
因此关于应用变量请参考后面的内容
</callout>

## **用户变量**的使用场景

看到上面的一堆讲解，你可能会产生一个疑问：

“大圣，看完你的教程，我知道了**用户变量**如何使用了，但是我在什么时候用呢？

在一个工作流中设置和读取，感觉没必要呀？”

你的疑惑是对的，在单个工作流中进行变量的设置和读取确实会有点没必要。

**但是变量在多工作流中有大用，因为变量的值可以在多个工作流和多个Agent中共享**

而且**用户变量**可以提供针对这个用户永久性的存储。

下面我们使用一个例子来体会用户变量的作用

假设你设计了一个智能体，你希望用户在使用你的智能体的时候首先需要告诉你他的姓名，然后这样你每次就可以用这个姓名称呼他了。

并且你会把他的姓名存储下来，这样一旦他设置了姓名，下一次就不需要了。

这样做到了两件事情：

1. 用户只需要设置一次姓名，后面就不需要设置了
2. 这个智能体的每个工作流都可以读取这个变量

<callout emoji="💡">
1. **用户变量可以用来进行不同工作流之间的通信（传递数据）**
2. **用户变量可以永久的存储单个用户的一些数据**
</callout>
