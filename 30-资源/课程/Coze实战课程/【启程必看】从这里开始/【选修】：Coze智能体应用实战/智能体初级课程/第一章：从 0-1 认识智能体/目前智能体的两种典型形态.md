# 写在前面

大家好，我是大圣，这节课想跟大家讲一下目前智能体存在的两种典型形态

这里我先要讲明白，任何一门技术都有发展的阶段，而不是一开始就能达到理论的状态

比如自动驾驶，他的终极形态肯定是无需要人做任何干预，完全自动化

但是在技术的发展过程中，我们会是一个阶段一个阶段的来走，中间也会调整各种技术路线

智能体也同样，他的理论形态肯定是人只管提出需求，剩下的都交给智能体，还能完成的符合预期

但是这有很长的路要走，中间也会有各种技术路线的诞生

这节课要讲的就是目前智能体存在的两种典型形态

- 工作流模式
- 大模型自主规划模式

理解了上述两种模式，你基本就能完全看懂，当前市场上所有的智能体产品

# 规划的实现决定了智能体的形态

我在讲智能体的时候会引入一个公式：

<callout emoji="🚅">
**AI Agent（智能体） = LLM（大模型）+ Planning（规划）+ Memory（记忆）+ Tools（工具）**
</callout>

这里面其中一个关键就是 Planning（规划）

<callout emoji="❤️">
**Planning（规划）**
- 类似于我们的执行控制系统
- 制定写书计划：**从资料搜索、大纲制定到成稿的完整工作流**
- 在智能体中担任制定工作流程的任务
</callout>

规划目前有两种经典的实现方式（扣子官方提供了对应的两种产品形态）

第一种：以**扣子开发平台**为代表的工作流编排模式

第二种：在**扣子空间**为代表的大模型自主规划模式

# 工作流编排模式

这也是我们整个智能体课程重点要学习的部分

大家这里可能对扣子还不是很了解，没有关系，大家不要在意操作细节，而是理解背后传达的逻辑

工作流编排模式本质就是搭建一个确定的流程，每一个包含特定功能的智能体都需要人去搭建完成

我举个例子，假设你搭建了一个从做杭州到北京旅游计划的智能体

你需要把这个智能体的工作流程提前编排好，例如：

第一步：确定起止日期，预算金额

第二步：查询航班，确定行程的价格和时间

第三步：查询天气，确定 3 天的天气情况

第四步：规划旅游景点

第五步：产出一篇攻略文档，交给用户

然后当用户每次使用你搭建的智能体的时候，都会按照上述 5 步来进行处理，不会有任何偏差

# 大模型自主规划

这个其实就是更高级的形态，不需要手动编排工作流，由大模型本身来理解任务，规划任务

这类形态目前有另一个名称叫做：通用智能体

换句话说：**他的愿景是处理一切任务，而不是人专门去搭建某类任务的智能体**

这时候，当你使用通用智能体做杭州到北京的旅游计划时，你只需要提出你的需求，然后提交任务

比如你的需求

<callout emoji="🏝️">
我要做一个从杭州到北京的 3 天旅游计划，明天出发，预算 3000 块
</callout>

然后这个通用智能体就开始工作，他的规划步骤完全由大模型给出，因此每次可能都会不一样

比如：他可能先查询天气，也可能先查询航班

AI会按照自己对任务的理解规划最优路径，然后执行

注意：这里的最优路径是理想状态，完全取决于那个专门做规划大模型的规划能力

# 优缺点

人工编排工作流的模式流程固定，非常适合企业端那种有固定 SOP的场景

缺点就是需要人工编排，搭建的过程复杂

大模型自主规划模式的优点就是使用简单，擅长执行通用型任务

比如制定旅游规划这类任务，因为大模型有大量的数据进行训练，所以他的规划比大多数人要好

缺点也很明确，由于规划过程完全由 AI搞定，每次的执行流程不确定，对于那种追求确定型的场景很不友好

# 发展展望

我们看待任何一个事物都要从长期和中短期来看

长期来看，一定是大模型自主规划是长期的发展目标，因为科技的进步就是希望减轻人的工作

不管是通用智能体，还是垂类智能体，都可以通过训练对应大模型实现比人手动搭建要好的规划

但中短期来看，工作流搭建模式会是核心，因为大量的企业有其自己特殊的流程，这个流程属于自身的业务，大模型不可能做出合理规划

对于个人而言，我给到的建议是

第一：充分了解这两种形态的原理和使用场景

第二：掌握几个比较好用的工具（例如扣子工作流和扣子空间）

第三：当遇到问题时，有针对性的选择合适的工具，**优先尝试大模型自主规划是否可以满足需求**，毕竟简单
