# 写在前面

大家好，我是大圣，这节课我们来讲一下 Coze 平台的发展历程。

你可能会问：为什么要讲发展历程？直接教我怎么用不就行了吗？

是Coze 发展到今天，它的页面确实稍显复杂，有好几个产品入口。

如果你不了解它的来龙去脉，很容易迷茫：这是什么？那是什么？它们之间是什么关系？

所以这节课非常重要。

我会带你了解 Coze 的来时路，它是怎么一步步发展成现在这个样子的。理解了这个，后面的学习你会清晰很多

# 第一阶段：工作流编排时代

我们先回到 2024 年 3 月左右

那时候我是最早一批接触 Coze 的用户，Coze 刚上线没多久。我们课程的第一个版本也是在这个时间段是上线的（2024 年 6 月）

那时候它只有一个核心功能：工作流编排

什么意思呢？就是我们前面讲过的，你要做一个智能体，需要自己动手去搭建工作流：这个节点连那个节点，设置触发条件，配置参数等等

你可以把它理解为一个低代码平台。

这就是 Coze 最初的样子：简单、纯粹，就是让你手动搭建智能体

# 第二阶段：扣子空间诞生

后来，行业里发生了一件大事：一个叫Manus的产品上线了。

大家没有听过 Manus也没有关系，这是一个里程碑式的产品。它意味着什么呢？

意味着**大模型自主规划的智能体来了**

他的理念是你不再需要自己动手搭建工作流了。你只需要用自然语言说清楚你的需求，AI 就能自主帮你规划、自主执行

这是一个巨大的变化，同时也创造出一个全新的产品形态

于是，Coze 也跟进了，上线了第二个产品：扣子空间

到这个阶段，Coze 的产品矩阵变成了四个：

| **产品** | **定位** |
|-|-|
| 扣子空间 | 大模型自主规划，不用手动搭建 |
| **扣子开发平台** | **手动搭建工作流** |
| 扣子罗盘 | 调试、监控、运维 |
| 代码框架 | 开源代码，面向开发者 |

# 第三阶段：扣子编程时代

讲到这里，我想多说两句：为什么 Coze 要把名字从开发平台改成扣子编程？

**这背后其实是一个战略设计**

首先，非技术背景的同学不要慌。在 AI 时代，编程早已不是程序员的专属技能了

你想一下，什么是编程？

- 你用代码写程序，是编程
- 你用低代码拖拽节点，是编程
- 你用自然语言口喷让 AI 生成工作流，本质上也是编程

**编程是一个更通用、更顶层的概念。**

它的本质是什么？是**让机器按照你的意图去执行任务**。

不管你用的是代码、低代码、还是自然语言，只要你在指挥机器干活，你就是在编程。

我觉得 Coze 团队已经意识到了这一点：我们正在进入一个**人人都是编程开发者**的时代

**所以它抢占了这个顶层入口，直接叫扣子编程**

这个名字告诉你：

- 你可以口喷，这是编程
- 你可以手搓低代码，这也是编程

**不管你是什么背景，用什么方式，你都是在编程**

这就是 Coze 的战略意图：**它不只是一个工具，它想成为 AI 时代每个人的编程入口**

---

所以现在 Coze 的产品矩阵变成了：

| **产品** | **定位** |
|-|-|
| 扣子空间 | 大模型自主规划 |
| 扣子编程 | 可手搓、可口喷工作流 |
| 扣子罗盘 | 调试、监控、运维 |
| 代码框架 | 开源代码 |

这就是扣子从诞生到现在的三个发展阶段。

很多朋友可能搞不清楚扣子产品之间的区别，我现在给你讲明白

我们整个课程都是围绕一个核心展开的：**智能体，也就是 AI Agent**。

那这三个产品和 Agent 是什么关系呢？

| **产品** | **一句话定位** | **和 Agent 的关系** |
|-|-|-|
| **扣子空间** | **它本身就是一个 Agent** | **一个通用型 AI Agent**，你提需求，它直接帮你完成 |
| **扣子编程** | 它是**搭建** Agent 的平台 | 你在这里创造自己的 Agent，不管是手搓还是口喷 |
| **扣子罗盘** | 它是**运维** Agent 的工具 | Agent 上线后，在这里监控、调试、看日志 |

这三个产品，覆盖了 Agent 的**使用、搭建、运维**三个环节

当然，扣子编程中你创建的 Agent，也可以直接使用。

**我们课程的主战场在哪里？在扣子编程**，原因如下：

- 扣子空间本身就是通过提示词来提交需求，核心是你的提示词的能力 + 模型本身的能力，没有太多要学习的内容
- 扣子罗盘是 Agent的运维，当你真正需要商业化的时候，需要学会看一些数据即可

扣子编程发展到现在，有两种方式可以搭建智能体

- 你通过自然语言来搭建智能体和工作流
- 你通过手动编排的方式搭建智能体和工作流

讲到这里，你可能会问：**既然现在可以口喷搭建了，那我们为什么还要学手搓工作流？**

这个问题非常好，我必须跟大家说清楚。

本系列课程的重点，依然是手搓工作流。

为什么？

**第一，口喷其实没什么好讲的**

口喷的本质是什么？就是你能不能把需求表达清楚。说白了，就是提示词。

提示词我们前面已经讲了很多了，对不对？所以关于口喷、关于自动化，未来只会越来越简单，反而没什么可讲的。

**第二，底层逻辑依然是手搓**

这才是关键。

今天 Coze 的底层逻辑，本质上还是工作流编排。AI 口喷出来的东西，最终生成的还是工作流。

如果你不了解底层逻辑，会发生什么？

口喷出来的工作流出了问题，你根本不知道哪里错了，更不知道怎么改。你只能干瞪眼。

这就像 AI 编程一样：AI 帮你写了一堆代码，报错了，你完全看不懂，那这个 AI 对你来说就是黑盒，你根本用不起来。

所以我常说：想学好 AI 编程，最重要的还是要懂编程。想用好 Coze 口喷，最重要的还是要懂工作流。

当然，你也可以选择等：等到它完全自动化、完全不需要人工干预的那一天再来学。

但我告诉你，到那一天，学习就没有意义了。

因为那时候人人都会用，你没有任何优势

# 写在最后

扣子的迭代过程其实就是 AI Agent发展的一个缩影，这也是为什么我要选择扣子平台去讲解 Agent的原因

另外，我想让你清楚一件事情，扣子未来肯定还会迭代，但是万变不离其宗，而且越迭代只会越简单。

我希望你可以理解背后的逻辑，当他再次迭代的时候，你自己可以看穿背后的本质
