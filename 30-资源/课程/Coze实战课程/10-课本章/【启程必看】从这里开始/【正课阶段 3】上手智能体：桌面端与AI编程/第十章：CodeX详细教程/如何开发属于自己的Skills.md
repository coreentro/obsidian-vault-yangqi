# 写在前面

你好，我是大圣

当市面上没有现成的 Skill 供我们选择的时候，我们就要从 0 到 1 开发属于自己的 Skill

这节课，我把我开发 Skill 的技巧分享给大家

# 一、Skill的框架

Skill的本质就是输入、处理和输出，这个框架看似简单，但无比重要

[[【必看理论】打磨Skill之前的思维模型]]

# 二、你需要首先安装一个官方技能

我们再次回到套娃的思维

Skill 既然是一套文件夹的规范，那么我们就可以让CodeX帮我们根据这套规范来创建 Skill

Anthropic 官方提供了一个技能，叫 Skill Creator，专门用来辅助开发者通过自然语言创建属于自己的 skill

https://github.com/anthropics/skills/tree/main/skills/skill-creator

当我们拿到一个新技能的时候，不要急着安装，而是先让 AI 帮我们阅读一下它的能力

你会看到：**这个技能它是一个元技能，是用来造技能的技能**

# 三、开发技能的第一种方式

第一种是最直接的方式：你脑子里已经有做成这件事的 SOP

然后你可以把这些 SOP 写成一篇文档，这篇文档里介绍了：

1. 这个业务的背景是什么
2. 它的步骤是什么
3. 它的验收标准是什么

这篇文档没有任何特殊的技巧，就相当于你要在公司写一篇教程。让新人员工照着你的教程能够快速上手

**这时候你要把 AI 当成一个能力强大的实习生，他除了不懂你的业务，他别的什么都懂**

**你只要能把这个业务流程描述清楚，它就能帮你转化成 skill**

# 四、开发技能的第二种方式

你看到了一篇文章，这篇文章里讲了一个完整的方法论

你把这篇文章丢给 AI，然后跟他讲说：

<callout emoji="✨">
你先帮我看一下这篇文章讲了什么？
它里面那个方法论应该对我很有用。我想把这个方法论打造成一个 Skill，这样以后能够随时为我所用
你在看完文章之后，做如下几件事情：
第一步：判断一下这篇文章核心讲了什么？
第二步：这篇文章的方法论适用于哪些场景？
第三步：如果要把这篇文章的方法论打造成一个 skill，我们该如何做？
</callout>

# 五、开发技能的第三种方式

**这种方式就是站在巨人的肩膀上去打磨**

在前面的课程里，我们讲了如何寻找 Skill：[[如何寻找 & 安装Skills]]

当你找到别人的开源 Skill 之后，你可以把它丢给你的 CodeX，让它先帮你安装在你的电脑上，然后基于这个 Skill 进行二次打磨

如何进行二次打磨呢？

这里没有特殊的技巧，就是你能把你的需求讲清楚

# 六、开发技能的第四种方式

这种方式相对来讲是最复杂的：**你想做一件事，但是你不知道怎么做**

这个时候你就打开一个 CodeX 的对话框，从一个非常模糊的需求开始跟 AI 去聊

通过不断的多轮对话，最终 AI 会给出符合你需求的答案

然后在对话的最后，你告诉 AI 说：我觉得这个过程非常有价值，我想把这个过程沉淀成一个Skill，你来帮我做这件事儿

当你需要用这种方式去开发技能的时候，它就比较考验你跟 AI 协作的能力：

1. 你的提示词能力
2. 你对 AI 的能力边界是否清楚

这种方式我就没有太多的技巧分享给大家了，简单来说，就是你要在了解 AI 底层逻辑的基础上，通过大量的使用来找到手感

# 七、开发技能的万能公式

这四种方式表面上不一样，但本质上都在做同一件事：

**把一次性的经验，沉淀成可重复调用的流程**

所以我自己有一个开发 skill 的万能公式

<callout emoji="✨">
**Skill = 高频场景 + 清晰 SOP + AI 打磨 + 输入输出模板 + 验收标准 + 持续迭代**
</callout>

我展开来说：

**第一，你要找到一个值得封装的场景**

不是所有事情都值得做成 Skill

真正适合做 Skill 的事情，一般有三个特点：你经常做、每次做都有相似流程、做好之后价值很高

**第二，你要把隐性的经验写成显性的 SOP**

这个 SOP 可以来自你自己的经验，也可以来自别人的文章、视频、课程、开源项目，甚至可以来自你和 AI 的一段高质量对话。来源不重要，重要的是它最后要变成清楚的步骤

**第三，你要借助 AI 帮你打磨 SOP**

很多人以为开发 Skill 是写代码，其实更核心的是写清楚业务流程

Skill 中会有代码的部分，但这个代码一定不是你写，而是 AI 来写

**你在开发 Skill 的过程中，一定要把自己当成产品经理，而不是程序员**

AI 最擅长的事情，就是帮你把一团经验整理成结构：适用场景、操作步骤、判断标准、输出格式、注意事项

**第四，你要定义输入和输出**

一个 Skill 最怕边界模糊

你要告诉它：用户会给你什么材料？你要怎么处理？最后交付什么结果？

**第五，你要设计验收标准**

没有验收标准，Skill 就会越跑越飘

比如朋友圈写作 Skill，“写得好一点”，这种不算验收标准，这是许愿

你可以说：是否有真实场景？是否有观点？是否像人话？是否有个人经历？是否能引发互动？

**第六，你要用真实案例不断迭代**

这也是最重要的一点：Skill 绝对不是一次性写完的，它是跑出来的

每一次使用，都是一次测试。哪里输出不稳定，哪里步骤不清楚，哪里判断标准不够准，就回头改 Skill
