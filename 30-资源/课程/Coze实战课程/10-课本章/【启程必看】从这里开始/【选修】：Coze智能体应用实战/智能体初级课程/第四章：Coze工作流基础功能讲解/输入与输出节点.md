# 输入节点：与用户互动的桥梁

## 什么是输入节点？

输入节点就像是一个智能收集器，**它可以在工作流运行过程中暂停下来，等待用户提供必要的信息。**

这个节点跟问答节点类似，大部分情况下我们都会使用问答节点，而不是输入节点

这就像在点餐时，服务员会询问你的具体需求一样。

## 使用场景

- **需要用户补充信息时**
- 工作流执行过程中需要额外数据时
- 实现多轮对话交互时

## 支持渠道

目前仅支持：

- 扣子商店
- 豆包
- OpenAPI

具体使用方法请参考教学视频

# 输出节点：提升用户体验

## 什么是输出节点？

输出节点就像是工作流中的"中间报告"。（**之前的消息节点**）

**可以在流程未完成时就给用户反馈，避免用户等待时间过长。**

## 核心特性

- **流式输出**：像打字机一样逐字显示
- **非流式输出**：一次性显示全部内容
- **支持卡片绑定**：可以展示更丰富的交互效果

## 配置要点

**输出变量（Output variable）**

- 可定义多个变量
- 支持固定值或引用上游节点

**输出内容（Answer content）**

- 使用{{变量名}}引用变量
- 支持文本格式化

**流式输出设置（Streaming output）**

- 默认为非流式
- 需要在大模型节点之后才能启用

# 实际案例

## 功能描述

我们要创建一个旅行助手，它可以：

1. 询问用户想去的城市
2. 获取用户的预算范围
3. 根据这些信息推荐景点和美食
4. 分步骤展示信息，提供良好的用户体验

## 工作流设计

```SCSS
开始节点 → 输入节点(城市) → 输出节点(确认) → 输入节点(预算) → 大模型节点 → 输出节点(景点) → 结束节点(美食)
```

#### A. 第一个输入节点（城市选择）

```SCSS
变量名：city

变量类型：String

描述：请告诉我您想去哪个城市旅游？

是否必选：是
```

#### B. 第一个输出节点（确认信息）

```Diff
输出变量：
- 名称：city
- 值：引用自city

输出内容：
"好的，我看到您想去{{city}}旅游！
接下来请告诉我您的预算范围，这样我可以为您推荐更合适的行程。"

开启流式输出：是
```

#### C. 第二个输入节点（预算输入）

```Markdown
变量名：budget
变量类型：String
描述：请输入您的预算范围（例如：3000-5000元）
是否必选：是
```

#### D. 大模型节点

```Markdown
系统提示词：

你是一位专业的旅游顾问，需要根据用户的城市和预算推荐合适的景点和美食。

用户提示词：

请为计划去{{city}}旅游，预算{{budget}}的用户推荐：
1. 3个适合预算的景点，包括门票价格
2. 3家当地特色美食店，包括人均消费

请将景点和美食分成两个段落输出。

输入JSON格式如下：
{
    "spots":"这是景点信息",
    "foods":"这是美食信息"
}
```

#### E. 第二个输出节点（景点信息）

```Diff
输出变量：
- 名称：spots
- 值：引用大模型输出的第一段（景点信息）

输出内容：
"🎯 根据您的预算，为您推荐以下景点：

{{spots}}

正在为您搜索美食推荐，请稍候..."

开启流式输出：是

```

#### F. 结束节点（美食信息）

```Diff
输出变量：
- 名称：foods
- 值：引用大模型输出的第二段（美食信息）

输出内容：
🍜 这些美食一定不要错过：

{{foods}}

祝您旅途愉快！如需了解更多信息，随时询问我。
```

## 效果展示

用户对话流程将是这样的：

```CSS
用户：我想规划一次旅行
机器人：请告诉我您想去哪个城市旅游？
用户：西安
机器人：好的，我看到您想去西安旅游！
       接下来请告诉我您的预算范围，这样我可以为您推荐更合适的行程。
用户：3000-5000元
机器人：[流式输出景点信息]
       🎯 根据您的预算，为您推荐以下景点：
       1. 兵马俑博物馆（门票150元）...
       
       正在为您搜索美食推荐，请稍候...
       
       [最终输出美食信息]
       🍜 这些美食一定不要错过：
       1. 老孙家肉夹馍（人均25元）...
```
