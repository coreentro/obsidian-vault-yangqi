## 大模型的缺陷

大模型的缺陷

- 由于训练数据的时效性，导致大模型无法回答训练数据日期之后的知识
- 由于大模型使用的是公开数据，针对企业私有数据的问题，无法进行回答
- 由于上下文（Token）的限制，无法处理长文本

而AI Agent的出现则是为了解决这一问题

## AI Agent概念

<callout emoji="💡">
**为什么要花时间讲AI Agent？**
因为Coze和AI Agent有着密不可分的关系
- **Coze是基于AI Agent的技术概念落地的产品**
- **在Coze上捏Bot其实就是在创建一个个的AI Agent**
因此只有在了解了AI Agent之后，才可以更好的理解和使用Coze
</callout>

Agent 翻译为代理人、代理商：帮助我们完成某一类功能的实体，可以是人，可以是机器，也可以是应用程序

**AI Agent则是应用了大模型能力的Agent。**

**以GPT为代表的大模型的出现，将Agent的能力提高到了前所未有的高度。AI Agent又被称为智能体**

在没有AI Agent之前，我们先考虑一个场景：我们要写一本20万字的关于人工智能最新技术的书

> - 第一步：先使用搜索引擎搜索一些相关书籍和信息进行阅读，为我们打开思路
> - 第二步：形成本书的大纲，并且考虑清楚每一章节要编写的内容
> - 第三步：针对每一个章节进行内容的编写，在编写过程中可能会调整文章的大纲
> - 第四步：在编写后面章节的时候可能会忘记前面写的内容，需要去翻阅前面已经写的内容
> - 第五步：文章初步完成之后，我们可能会找相关专业人士帮忙修改
> - 最后：经过几番调整之后，书籍最终成型

于是你开始优化提示词，写了一段很复杂的提示词，可以让大模型做到先写大纲，再写内容，还会扮演不同的角色通过讨论对内容进行优化。但是缺点如下：

- 单独的大模型因为训练数据的原因没有办法获取最新的人工智能技术
- 大模型没有记忆的能力，由于上下文的限制，无法一次性完成20万字的文章，会造成前言不搭后语的现象
- 因为要完成先写大纲，再编写每个章节，然后和别人讨论的逻辑，提示词会非常的复杂

## AI Agent的核心公式

直接说结论

<callout emoji="💡">
**AI Agent  =  LLM（大模型） + Planning（规划） + Memory（记忆） + Tools（工具）**
这个公式是贯穿全文的主线，请务必理解
</callout>

**这里的大模型更准确的表述：LLM（大模型+提示词）**

**我们也可以认为LLM + Planning + Memory是人类的大脑，而Tools则是人类的四肢**

我们继续拿上面写最新人工智能书籍的例子来讲

> 1. **LLM（大模型+提示词）**：就像我们人类大脑的核心部分
> 2. **Planning（规划）**：就是如何写书这个流程：先搜索，再写大纲，在与人讨论等等，俗称**工作流**
> 3. **Memory（记忆）**：这类似于我们写书时使用的笔记本或者电脑，可以让我们随时回看已经写过的内容。
> 4. **Tools（工具）**：比如谷歌浏览器，让我们可以获取最新的信息

## AI Agent会一直存在么

我们可以思考一个问题，为什么会诞生AI Agent这个概念，以及产生那个很重要的公式

**AI Agent = LLM（大模型） + Planning（规划） + Memory（记忆） + Tools（工具）**

所有新的技术概念都是为了解决问题而存在。

AI Agent概念的出现则是为了解决LLM不够强大的问题

- 如果大模型的上下文足够长，推理能力足够强大，根本不需要用知识库，也就是所谓的记忆能力
- 如果大模型的推理能力足够强，就不需要专门的规划算法了
- 如果算力和技术允许，大模型可以被实时训练，那么大模型本身就可以拥有最新的网络知识，也就不需要使用搜索引擎来获取实时数据了
- ....

这一块我没有讲的那么专业，我的目的是为了引出下面这一环节，要对智能体进行祛魅

# 二、智能体去魅

这一部分的内容是想让你不要神化智能体这个概念。

## 现在市面上的智能体到底是什么

我们前面讲到了一个公式：**AI Agent = LLM（大模型） + Planning（规划） + Memory（记忆） + Tools（工具）**

那是不是只有包含了大模型 + 规划 + 记忆 + 工具的Agent才能被称之为智能体？

当然不是，上述的公式描述的是一个智能体的完全体，我希望用另外一个话来描述智能体

**只要能解决你特定问题的Agent就可以被称之为智能体**

- 如果你要解决写普通公文的需求，大模型 + 提示词就是足以满足你需求的智能体
- 如果你要解决大模型没有实时数据的痛点，大模型 + 搜索引擎（工具）就是可以满足你需求的智能体
- ....

**所以智能体的关键不在于他有多复杂，而是他是否能解决你的问题**

## 构建智能体的原则

构建智能体有两个核心原则：

- 思考清楚自己的需求
- 了解当下AI Agent的能力边界

  - 大模型+提示词的能力边界，哪些需求可以用提示词解决
  - 规划是为了解决什么问题？
  - 记忆是为了解决什么问题？
  - 工具是为了解决什么问题？

如果想要构建一个满意的智能体，你需要从这上述两个方面去思考，这样才能构建一个符合自己的需求的智能体。

**构建智能体的原则我们会专门出一期加餐教程，但在这次课程不是讲解重点，只是让大家意识到他的重要性！**

## 业务背景

在复杂的业务场景下，就需要分析业务背景。

在当今竞争激烈的市场环境中，客户服务质量直接影响企业的口碑和客户的忠诚度。传统的客户服务方式通常依赖于人工客服，这不仅增加了企业的人力成本，还可能导致响应速度慢、服务质量不一致等问题。随着人工智能技术的快速发展，智能客服系统逐渐成为企业提升客户服务质量和效率的重要手段。

## 需求分析

1. 业务需求

   - **快速响应客户咨询：客户希望在短时间内获得准确的答案，减少等待时间。**
   - **提高服务质量：提供一致、专业的回答，提升客户体验。**
   - **降低人力成本：减少对人工客服的依赖，节省成本。**
   - **全天候服务：提供7x24小时的服务，满足客户随时咨询的需求。**
2. 技术需求

   - **知识库管理：系统需要能够管理和更新大规模的知识库，确保回答的及时性和准确性。**
   - **自然语言处理能力：系统需要具备强大的自然语言理解和生成能力，能够处理各种复杂的客户问题。**
   - **信息检索能力：系统需要能够从知识库中快速检索出相关信息，以辅助生成高质量的回答。**
   - **多渠道支持**：系统需要支持多种客户接触渠道，如网站、微信、App等，方便客户随时随地进行咨询。
3. 用户需求

   - **用户友好界面**：提供直观、易用的用户界面，方便客户使用。
   - **个性化服务**：能够根据客户的历史记录和偏好，提供个性化的服务和推荐。
   - **问题追踪和反馈：能够记录客户的咨询历史，便于后续跟踪和反馈。**
4. 安全需求

   - **数据安全和隐私保护**：保障客户数据的安全，遵守相关法律法规，防止数据泄露和滥用。
   - **系统稳定性和可靠性**：确保系统的稳定运行，避免因系统故障导致的服务中断。

# 八、Bot的调试技巧

在搭建Bot完成之后，最关键也是最烦人的一个环节来了，那就是调试Bot。

调试Bot一般有这么几个环节

- 调试工作流

  - 是否有功能节点报错
  
    1. 定位到报错节点
    2. 首先排查入参是否都有正确配置
    3. 再排查入参参数是否符合预期
    4. 如果是代码节点、数据库节点等，要排查是否是代码错误或者SQL语法错误
  - 工作流的执行速度是否过慢
  
    1. 首先找出运行慢的节点（一般是大模型节点）
    2. 如果输出质量等同，优先选择低阶模型，因为低阶模型速度更快
  - 大模型的输出质量是否符合预期
  
    1. 修改提示词，不断进行测试
    2. 如果修改提示词不行，可能要换更加优秀的大模型
- 调试Bot

  - 是否可以按照预期的调用工作流
  
    1. 修改提示词，使用测试用例进行测试
  - 是否可以将用户输入正确的传递给工作流
  
    1. 使用Bot的dubug模式，查看信息的流转

# 九、市面上的AI Agent工具对比

万变不离其宗，我们来看AI Agent的核心公式

**AI Agent  =  LLM（大模型） + Planning（规划） + Memory（记忆） + Tools（工具）**

对比AI Agent工具，我们只要从公式的四个方面进行对比即可。

- Dify
- Coze

- 百度的千帆
- 智谱清言/Kimi Chat
- .....

## 大模型纬度

### 是否支持接入大模型API

如果支持大模型API则代表你可以不受平台的限制，利用API能力来享受各种大模型的能力。

但是如果使用自己的API，那么在使用大模型的时候就需要自己付费

| Kimi Chat | 不支持 |

### 支持的大模型种类

PS：如果支持API接入大模型，那么理论上来说就可以支持所有的大模型

| 智能体平台 | 支持的大模型种类 |
|-|-|
| Coze | 国内：Kimi系列、豆包系列、通义千问系列....  <br/>国外：GPT系列，Gemini系列... |

| 百度的千帆 | 未知 |

| Kimi Chat | 自己家的大模型 |

### 总结

<callout emoji="🌅">
在进行AI Agent对比的时候，首先考虑大模型纬度，要判断这个AI Agent是否支持接入大模型的API
- 支持接入API

  - 优点：扩展性好，可以接入任意的API，速度可能更快，不用跟其他人抢资源
  - 缺点：自己的API需要付费，而且如果接入GPT系列，还需要解决网络问题
- 不支持接入API，提供了多种大模型

  - 优点：免费白嫖，用起来不心疼
  - 缺点：跟大家共用资源，可能不稳定。没有办法扩展自己想要的模型
</callout>

## 私有化部署纬度

这个维度则是部分人比较关心的数据安全问题，尤其是有搭建知识库需求的企业，他们会比较担心数据上传之后是否会有泄漏。

这里你就记住一句话：

- 支持私有化部署的则数据是安全的
- 如果不支持私有化部署的AI Agent工具，那么数据就存在泄漏的风险

所谓的私有化部署，简单理解就是：所有的数据都在你自己的机器上。除非网络攻击，否则你的数据不会泄露
