# Obsidian 知识库

> 把知识库做成跨项目长期记忆系统：结构稳定、AI 可检索可维护。


## 📋 项目背景

唯一有效库：`~/Library/Mobile Documents/iCloud~md~obsidian/Documents/yangqi`（iCloud 同步，git 版本管理，约 1300 篇笔记，588MB）。
主库已完成 PARA+Maps 结构化；本阶段目标是加一层**长期记忆**，让任何一次新对话都能接上上次进度，而不是每次从零解释。

## 🎯 长期偏好与约束

- **不删笔记正文**，不改写知识内容；结构调整只做移动与新增。
- `assets/` 永远留在根目录（避免大量图片链接失效）。
- 不把课程拆成原子笔记（除非明确要求）。
- 不强制 Zettelkasten 化。
- 忽略 `Documents/文稿 - …/Obsidian Vault` 这个空的次级库。

- `2026-08-17` **新增顶层 `50-记忆/` 承载长期记忆**，不塞进 `10-项目` — PARA 是按行动性分的，记忆是元层。详见 [[50-记忆/02-决策记录]]

## ❌ 失败方案

- 大批量移动时循环调用几百次 CLI `move` → 单次就可能卡 60–180s，整体必然超时。改用 `shutil.move` + Python 批量改链接前缀。

## 🕳️ 踩坑

- 只做应用内更新 → `obsidian-cli` 仍是旧安装器，`obsidian version` 报错；要换 DMG 替换 App 再 `xattr -cr`。
- 路径型链接 `[[科研/…]]` 移动后会断，名称型链接一般不受影响。
- 详见 [[50-记忆/03-踩坑与失败方案]]

## 🧪 技术方案

- 认库：`~/Library/Application Support/obsidian/obsidian.json` 里 `"open": true`
- 检索本层：`grep -ril "<KW>" "$V/50-记忆" --include="*.md"`
- 回滚：库内有 git，`git reset --hard <commit>`
- 详见 [[50-记忆/04-技术方案库]] · 维护规程 [[50-记忆/90-系统/维护规则]]
