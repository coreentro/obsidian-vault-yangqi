### 2026-08-17 | Hermes桌面端界面 | 放弃自制 UI 插件，聊天区保持原生外观
- 状态: 生效
- 背景: 用户反馈聊天区分不清谁说的。我先做了 `chat-role-contrast`（色条+标签）被否决，又做了 `chat-sides`（左右分栏）也被要求删除，用户明确要「去 GitHub 找成熟方案，别自己做」。
- 决定: 两版插件全部删除，`desktop-plugins/` 清空恢复原生。调研后确认**无现成方案**（官方 Issue #41302 未实现；社区 5.3k★ 目录无此插件），据实告知并搁置。
- 理由: 自制 CSS 依赖打包产物里的 `data-slot` 与内部类名，Hermes 升级后**随时可能失效**，长期是维护负担；用户明确不要这种脆弱方案。尊重用户判断优先于"我能做出来"。
- 代价: 分不清的问题暂未解决。低成本缓解路径已记录（切深色皮肤，`--theme-mix-bubble` 在 `.dark` 下为 46%）。

### 2026-08-17 | 通用 | 排查"某 App 是不是 Agent 启动的"必须看系统日志，不能看 PPID
- 状态: 生效
- 背景: Apple Music 在我执行命令时跳到前台，`ps` 显示其 PPID 正是 Hermes 服务进程（1910），看起来像我干的。
- 决定: 以 `log show` 的发起链为准。实测真凶是 `SenderBundleIdentifier=com.apple.bluetoothd` 发的 `Play` 指令（蓝牙设备误触），与 Agent 无关。
- 理由: macOS 的 GUI 应用由 `launchd`/`runningboardd` 启动，**PPID 会挂到当时活跃进程上，不代表发起者**。只看 PPID 会让我认下不属于自己的错，并把用户引向错误方向。
- 代价: 查日志比看 PPID 慢一步，但结论可靠。

### 2026-08-17 | Claude多中转 | 弃用本地 NewAPI `:3001`，改客户端直连各中转站

- 背景: 实测 `:3001` 没在跑（colima 未启动）。询问用户后，用户明确表示**不要了**。

- 理由: 用户不需要统一汇聚层；少一跳少一个故障点。保留文件符合用户红线（不主动删除），将来想恢复仍有余地。
- 代价: a–f 前缀不再由 NewAPI 统一渲染，退化为记忆里的站点代号；各客户端的模型前缀需各自配置。健康探测得逐站做，不能一个入口全测。

### 2026-08-17 | Claude多中转 | 健康探测改为「先查目录再选探针」，不再固定用 haiku
- 状态: 生效（取代「探测固定用 haiku」）
- 背景: 按旧口径用 haiku 探 anyrouter，恒返回 403「该令牌无权访问」。若直接下结论会误判"站点挂了"。实测发现该站目录里**根本没有 haiku**。
- 决定: 探测流程改为两步 —— ① `GET /v1/models` 取真实目录 ② 从目录里挑一个该站确有的模型当探针。
- 理由: 固定探针假设"所有站都有该模型"，一旦不成立就把**权限/目录问题**误报成**可用性问题**，排障方向整体跑偏。
- 代价: 每次探测多一次请求；不同站探针不同，不能直接横向比延迟。

### 2026-08-17 | Obsidian知识库 | 用独立 `50-记忆/` 承载跨项目长期记忆，而不是塞进 `10-项目`
- 状态: 生效
- 背景: 需要一个「新对话能立刻接上进度」的层；但主库已是 PARA+Maps，硬塞会打乱行动性分流。
- 决定: 新增顶层 `50-记忆/`，只放**状态与结论**（背景/偏好/决策/进度/踩坑/方案/下一步）；知识正文仍留在 `20-领域`、`30-资源`，用双链互指。
- 理由: PARA 的 10/20/30/40 是按行动性分的，长期记忆是**元层**，混进去会让「项目」失去「有终点」的语义；独立一层可以整层 grep，检索成本最低。
- 代价: 同一主题会存在「记忆卡 + 正文笔记」两处，需要靠链接和维护规则防止内容重复。

### 2026-08-17 | Obsidian知识库 | 每个项目一张记忆卡，固定九段式结构
- 状态: 生效
- 背景: 跨项目状态散落在聊天记录里，换会话就丢。
- 决定: `50-记忆/项目/<项目名>.md`，固定包含 背景／长期偏好／关键决策／已完成／当前进度／失败方案／踩坑／技术方案／下一步。
- 理由: 固定小节名 = 可预测的检索锚点，脚本和人都能直接定位；frontmatter 带 `status`/`updated` 便于排序。
- 代价: 小项目会有空小节（保留标题写「暂无」，不删，保证结构一致）。
