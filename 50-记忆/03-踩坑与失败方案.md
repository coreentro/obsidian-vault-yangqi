# 🕳️ 踩坑与失败方案

> **最贵的记忆。** 目的：同一个坑不踩第二次、已证伪的方案不再重试。
> 每条写清：现象 → 真因 → 正确做法。真因不明的写「疑似」，别硬编故事。

## 🌐 网络 / 代理

| 现象 | 真因 | 正确做法 |
|---|---|---|
| 探测 `127.0.0.1:<port>` 返回**瞬时 503（0.0s）** | **系统代理拦截了 localhost**，不是服务坏了 | Python 用 `build_opener(ProxyHandler({}))` 绕过代理；curl 用 `--noproxy '*'`。绕过后才看到真相（如 `Connection refused` = 服务没起）|
| 改了 Shadowrocket 配置但行为没变 | 生效的是 plist 里 `CurrentRuleFileName`（常仍是 `Basic.db`），**不是**刚覆盖的 conf | 改完 conf／切配置后重启 `MacPacketTunnel`，并确认三个键一致 |
| 某些站点 TLS 直接断开 | **节点 SNI / 机房 IP 被墙或被站点拉黑**，不是规则问题 | 换干净节点（避开机房 IP），不要反复改分流规则 |
| Cloudflare 站点转圈／验证不过 | 规则走了 DIRECT，或 DNS 泄漏 | 必须 `PROXY` + `force-remote-dns`；机房节点（如 JP BAGE）易卡真人验证，换干净节点或人工点验证 |

## 🖥️ macOS

| 现象 | 真因 | 正确做法 |
|---|---|---|
| GUI 应用突然跳到前台，`ps` 显示其 **PPID 正是 Hermes 服务进程**（易误判成 Agent 干的）| macOS 的 GUI 应用由 `launchd`/`runningboardd` 启动，**PPID 会挂到当时某个活跃进程上，不代表发起者** | **查发起链要看 `log show`，不看 PPID**：`log show --style compact --start "<HH:MM:SS>" --end "<HH:MM:SS>" --predicate 'eventMessage CONTAINS[c] "<App>.app"'`。日志里的 `SenderBundleIdentifier` 才是真凶 |
| Apple Music 无故自启并抢前台 | **蓝牙设备发了 `Play` 指令**：`mediaremoted` 收到 `SenderBundleIdentifier=com.apple.bluetoothd` → `requested a launch` → 系统拉起 Music | 排查蓝牙耳机/键盘误触（戴上、摘下、碰到多功能键或播放键）。与 Agent 无关，别改配置 |

| 现象 | 真因 | 正确做法 |
|---|---|---|
| 授权弹窗反复冒 + `computer_use` 截图全 `0x0` | **微信 Sparkle 自动更新循环**（不是权限问题） | 只改 `defaults` 无效；要用**只读文件占位**。详见 skill `wechat-sparkle-updater-loop` |
| 一跑截图就弹录屏授权 | Hermes.app 本地签名，TCC 记录永不匹配 | **禁止 `screencapture`**；看屏幕统一用 cua-driver |

## 🤖 模型 / Agent 工具链

| 现象 | 真因 | 正确做法 |
|---|---|---|
| Codex Desktop 侧边栏「历史消失」 | 侧边栏按 `model_provider` 过滤，切 provider 就看不到 | **只换 model，不换 provider**；供应商固定 `cliproxyapi` |
| `muyuan.do` 报 `403 client_restricted` | 缺 `User-Agent` 头 | `extra_headers` 里设 `UA=codex_cli_rs*`；CF 偶发 504 重试即可 |
| dsh 想用 Grok OAuth 登录 | **官方 dsh 只认 `DEEPSEEK_API_KEY`** | 走不通，别再试；Grok OAuth 用 `hermes auth add xai-oauth` 或 `grok login --oauth` |
| `dsh` 命令找不到 | PATH 里没有 | 用 `npx @deepseek-ai/dsh web` |
| `web_extract` 抓 GitHub 报 `Blocked: URL targets a private or internal network address` | fake-IP（198.18）触发 SSRF 误拦 | 改用 `curl` + GitHub API（`api.github.com/repos/<owner>/<repo>`）|
| `execute_code` 里 `terminal()` 返回 `KeyError: 'output'` | 长命令（brew install 等）超时，返回结构不含该键 | 取值用 `.get("output","")`；长任务直接用 `terminal` 工具并给足 `timeout` |
| Hermes 内置 browser 抓页面 403 | Browserbase 出口被 WAF 拦 | 改用本机浏览器 + 代理；见 skill `browser-tool-workarounds` |
| 中转站返回 `401 unauthorized client detected` / `403 client_restricted` | **客户端指纹门禁**：只放行白名单客户端。连 `curl` 和 `anthropic-sdk-python` 官方 SDK 都被拦 | 二选一：① `User-Agent` 以 `codex_cli_rs/` 或 `claude-cli/` 开头（版本任意）；② 任意 UA **＋** `originator: codex_cli_rs`。**只给 originator 不给 UA 无效**。已确认此类站：`agentrouter.org`、`muyuan.do`（`2026-08-17` 各复测 3 次稳定）|
| 健康探测某模型恒 403「该令牌无权访问」 | 该站**目录里根本没有这个模型**，不是站点故障 | 先 `GET /v1/models` 看真实目录，再挑该站确有的模型当探针。**别把 haiku 当通用探针** |
| 打包版 Hermes 桌面端查不到 DOM（CDP 端口不通）| packaged build **一律关闭** CDP 调试口，无环境变量可覆盖 | 解包读静态 CSS：`npx --yes @electron/asar extract /Applications/Hermes.app/Contents/Resources/app.asar /tmp/out`。skill `inspecting-hermes-desktop-dom` 只适用于 dev-server 运行 |
| `grep -oE` 报 `maximum repetition exceeds 255` | BRE/ERE 的 `{0,N}` 区间上限 255 | 改用 Python `re` 处理 |
| `rm -rf` 后续命令全报 `getcwd: cannot access` | 删掉了 shell 当前所在目录 | 删之前先 `cd` 到安全目录，或给命令显式 `workdir` |
| `grep -r` 在 `~/.hermes` 下炸出几万字 | `~/.hermes/sessions/*.json` 存的是**完整请求转储**（含历史 system prompt） | 检索配置只针对 `config.yaml`；**务必排除 `sessions/`**，否则污染上下文 |

## 📚 Obsidian

| 现象 | 真因 | 正确做法 |
|---|---|---|
| Agent 说「记忆里没有」但内容明明存在 | Hermes 工具的**上下文去重**：本会话已读过的文件，`search_files` 的 `matches_text` 返回空串、`read_file` 不返回 `content` 键（`total_count` 仍正确） | 判空前先看 `total_count`；拿不到正文就 `grep -rn` 兜底。另：`output_mode="files_only"` 在本库恒返回 0，别用 |
| 单次 `move`/`renameFile` 卡 60–180s+ | 大库全库改写 `[[链接]]` | 几十个文件用 `shutil.move` + Python 批量改前缀（最长前缀优先）；**不要**循环几百次 CLI move |
| `obsidian version` 报 CLI 未启用／installer 过旧 | 只做了应用内更新，**安装器仍是旧版** | 换最新 DMG 替换 `/Applications/Obsidian.app` → `xattr -cr` → 开 Advanced CLI 开关 |
| 移动后 `[[科研/…]]` 这类路径型链接失效 | 名称型链接能自动解析，**路径型不能** | 只改 `[[...]]` 里的路径前缀，不动正文散文 |
| 以为在整理主库，其实动的是空库 | `Documents/文稿 - …/Obsidian Vault` 是空的次级库 | 认 `obsidian.json` 里 `"open": true` 的那个 |

## ❌ 已证伪 / 不要再提的方案

- 用 launchd 让 DeepSeek Harness 开机常驻 → 用户明确要「像普通 App 双击打开」。
- 靠改分流规则解决节点被拉黑导致的 TLS 断开 → 无效，问题在节点。
- 只改 `defaults` 压制微信更新弹窗 → 无效。
