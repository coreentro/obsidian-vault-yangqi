# B 组 · 决定它答得准不准

> 这一组管一件事：**什么时候可以信它，什么时候必须自己核**。

---

## 1. 幻觉（Hallucination）

| | |
|---|---|
| 💬 **一句人话** | 它把**不存在的东西说得非常确定**：假的文献、假的函数、假的数据、假的网址 |
| ⏰ **什么时候有用** | 凡是涉及**具体的名字、数字、出处、条款、API** 时，默认"可能是编的"，先核再用 |
| ⚠️ **最容易误解** | ①以为幻觉是"偶尔犯错"——它的机制是**接着往下补最像的内容**，缺信息时补齐是本能，不是失误。②以为语气确定就说明可靠——**语气和可靠度无关**。③以为大模型/新模型就不幻觉——只是更少，不是没有 |

**追问句：**
```text
把你的回答分成两部分列出：
（A）你有把握的、可指向明确来源的
（B）你在推测或补齐的
（B）部分请标注"需要我自己核实"。不确定就说不确定，不要补齐。
```

> 💡 **最高危场景**：文献引用、法规条款、药品剂量、财务数字、API 参数名、命令行参数。这几类**一律核**。

---

## 2. 推理 / 思考（Reasoning · Chain of Thought）

| | |
|---|---|
| 💬 **一句人话** | 让它**先在草稿纸上算，再给答案**，而不是张口就答 |
| ⏰ **什么时候有用** | 多步计算、逻辑推导、条件很多的判断、代码调试、比较决策 |
| ⚠️ **最容易误解** | ①以为"推理模型"什么都更强——它更慢更贵，写文案、闲聊、简单改写用它是浪费。②以为它给出的推理过程就是它真实的思考过程——**那也是生成出来的文字**，过程看着合理结论仍可能错。③以为长篇思考等于更准 |

**追问句：**
```text
这个问题请一步一步来：
1. 先列出已知条件和你的假设；
2. 再列出推导步骤；
3. 最后给结论；
4. 最后自查一遍：哪一步最脆弱？如果哪个假设是错的，结论会怎么变？
```

---

## 3. 知识截止（Knowledge Cutoff）

| | |
|---|---|
| 💬 **一句人话** | 它的"书"是某个日期之前印的，**之后的事它不知道** |
| ⏰ **什么时候有用** | 问最新版本、最新价格、最近新闻、某个库的新 API、"现在最好的工具是什么" |
| ⚠️ **最容易误解** | ①以为它会主动说"我不知道最近的"——它往往用旧知识自信作答。②以为它知道**今天是几号**——通常不知道，除非被告知 |

**追问句：**
```text
这个问题涉及可能已经变化的信息。
你的知识截止到什么时候？这方面在那之后很可能已经改变吗？
如果你能联网，请查证后给出来源和日期；不能联网就明确告诉我"需要我自己查最新的"。
```

---

## 4. 联网检索（Web Search / Grounding）

| | |
|---|---|
| 💬 **一句人话** | **先去查，再来答**，并把出处贴给你 |
| ⏰ **什么时候有用** | 时效性问题、需要出处的问题、小众且具体的事实 |
| ⚠️ **最容易误解** | ①以为联网就一定准——它可能引用了内容农场、过期页面，或者**引用的链接和它说的内容其实不对应**。②以为"有链接"就等于"核实过" |

**追问句：**
```text
请检索后回答，并对每个关键结论标注具体来源链接和页面日期。
如果不同来源互相矛盾，把矛盾直接摆出来，不要合成一个折中答案。
```

> 💡 **实操**：拿到带链接的回答，**至少点开一个链接**看它是否真说了那句话。这一步能抓出大部分伪引用。

---

## 5. RAG（检索增强生成）

| | |
|---|---|
| 💬 **一句人话** | 给 AI 配一个**你自己的资料柜**：先从你的文档里找出相关段落，再据此作答 |
| ⏰ **什么时候有用** | 你有一堆自己的材料（论文、笔记、手册、合同），想让 AI 基于这些回答而不是凭记忆 |
| ⚠️ **最容易误解** | ①以为"上传了它就全读了"——它只读**检索到的那几段**，检索没找对就答不对。②以为 RAG 消除幻觉——它只是把幻觉从"凭空编"变成"基于找错的段落编"。③以为文件越多越准——**噪音材料会拉低命中率** |

**追问句：**
```text
回答时请明确标出你依据的是哪几段原文，把原文摘录出来。
如果我的资料里其实没有相关内容，直接说"资料里没有"，不要用通用知识补。
```

## 6. 引用与出处（Citation）

| | |
|---|---|
| 💬 **一句人话** | 每个结论都能指回**具体哪句话、哪一页、哪个链接** |
| ⏰ **什么时候有用** | 写论文、做汇报、做决策依据、任何要对结果负责的场合 |
| ⚠️ **最容易误解** | 以为格式规范的引用就是真引用。**编造的引用往往格式最漂亮**——作者、年份、期刊、DOI 一应俱全，但那篇文章不存在 |

**追问句：**
```text
每条引用请给出：标题、作者、年份、可访问链接或 DOI，
并注明该结论来自原文的哪一部分（章节/页码）。
你无法确认真实存在的引用，直接删掉，不要凑数。
```

> 💡 **实操**：核文献最快的办法是**拿标题去搜一遍**。搜不到就是编的。

---

## 7. 校准与自信度（Calibration）

| | |
|---|---|
| 💬 **一句人话** | 它**分不清自己知道和不知道**，所以自信程度不能当可靠程度用 |
| ⏰ **什么时候有用** | 任何"它说得很确定"的时刻，都该想一下这条 |
| ⚠️ **最容易误解** | 以为让它打个"置信度 85%"就解决了——那个数字也是生成出来的。但**要求它区分"有把握/推测"仍然有效**，因为这会改变它的表述方式和补齐倾向 |

**追问句：**
```text
如果你这个回答是错的，最可能错在哪一处？
有什么办法能让我用 5 分钟自己验证这一处？
```

---

## 📎 B 组速查：什么必须自己核

| 内容类型 | 是否必核 |
|---|---|
| 文献、引用、DOI | 🔴 **必核**（拿标题搜一遍） |
| 具体数字、剂量、金额 | 🔴 **必核** |
| 法规条款、合同条文 | 🔴 **必核** |
| API 参数名、命令行选项 | 🔴 **必核**（跑一次就知道） |
| 最新版本、最新价格 | 🔴 **必核**（有知识截止） |
| 概念解释、思路框架 | 🟡 大致可信，逻辑自己过一遍 |
| 文字润色、结构调整 | 🟢 基本可信，你自己就能判断 |
