# C 组 · 决定它能不能真的干活

> 这一组管一件事：**它是在"说"，还是真的"做"了**。
> 分界线只有一条：**有没有工具权限**。没有工具的 AI，说"我已经帮你改好了"都是在生成文字。

---

## 1. 模型 vs Agent（智能体）

| | |
|---|---|
| 💬 **一句人话** | **模型**是能力（会想会写）；**Agent** 是在模型外面套的一套流程，让它能规划、动手、看结果、改错重做 |
| ⏰ **什么时候有用** | 分清"它为什么做不到"：是能力不够（换模型），还是没给它手脚（换 Agent 环境） |
| ⚠️ **最容易误解** | ①**模型不是 Agent，Agent 不是模型**——同一个模型放在聊天窗里只能说话，放在 Agent 里能改文件。②以为 Agent 更聪明——它不更聪明，只是**能动手并且能循环** |

**追问句：**
```text
你现在有哪些工具权限？（能否读写文件、跑命令、联网、看图）
这个任务在你当前权限下能真正完成到哪一步？
哪些步骤必须我自己手动做？先说清楚，再开始。
```

> 💡 **一个 Agent 通常包含**：模型（想）+ 工具（做）+ 记忆（记）+ 计划（拆）+ 反馈（改）。
> 详见 [[20-领域/AI/AI时代的结构化语言认知地图]]。

## 2. 工具调用（Tool Use / Function Calling）

| | |
|---|---|
| 💬 **一句人话** | AI 能**真的去按按钮**：读文件、写文件、跑命令、查网页、调接口 |
| ⏰ **什么时候有用** | 你要的是**结果**（文件真的改了、脚本真的跑了），不是"教程" |
| ⚠️ **最容易误解** | ①**最贵的误解**：以为它说"我已经改好了"就真改了。没有工具权限时它只能生成"看起来像改好了"的文字。②以为工具调用一定成功——可能失败、可能改错地方，**要看它报回来的实际输出** |

**追问句：**
```text
做完之后，请把真实的执行证据贴出来：
改了哪个文件的哪几行（贴 diff）、跑了什么命令、命令的实际输出是什么。
不要只说"已完成"。如果某一步失败了，原样贴出错误信息。
```

> 💡 **这就是"说"和"做"的分界线**。要求贴证据，是最有效的一句话。

## 3. MCP（模型上下文协议）

| | |
|---|---|
| 💬 **一句人话** | 一种**统一插头标准**，让 AI 能接上各种外部工具（你的笔记库、数据库、日历、云盘），不用每家单独写对接 |
| ⏰ **什么时候有用** | 你想让 AI 直接读写某个具体应用里的东西时 |
| ⚠️ **最容易误解** | ①以为装了就万能——每个 MCP 服务只提供它自己那几个能力。②以为它安全无风险——**给出去的是真实读写权限**，装之前想清楚它能碰到什么 |

**追问句：**
```text
要让 AI 直接操作 ［某个应用］，需要什么条件？
它会获得哪些权限、能读到哪些数据、最坏情况能造成什么后果？
有没有只读的方案先试？
```

## 4. 记忆（Memory）

| | |
|---|---|
| 💬 **一句人话** | 分两种：**这一轮对话里的记性**（临时，关掉就没）和**跨会话的长期记忆**（写进档案，下次还在） |
| ⏰ **什么时候有用** | 你不想每次都重新自我介绍、重申偏好和背景时 |
| ⚠️ **最容易误解** | ①以为"我上次跟它说过"——**新对话默认从零开始**。②以为长期记忆什么都记——通常只记少量精简条目，且可能过期。③把**任务进度**塞进长期记忆——过几天就是误导 |

**追问句：**
```text
我这几条偏好希望你以后一直遵守：［…］
请判断哪些值得写进长期记忆（稳定的偏好和环境事实），
哪些不该写（临时任务进度、会过期的状态），并说明理由。
```

> 💡 **实操判据**：**一周后还成立的，才值得长期记住**。"我偏好中文回复"值得记；"这个 PR 已合并"不值得。

## 5. 结构化输出（Structured Output / JSON）

| | |
|---|---|
| 💬 **一句人话** | 让它按**固定格子**输出（表格、JSON、YAML），而不是自由写作文 |
| ⏰ **什么时候有用** | 输出要给程序接、要批量处理、要每次格式一致、要方便对比 |
| ⚠️ **最容易误解** | ①以为说一句"输出 JSON"就稳定——**要把字段名、类型、必填项、缺失时填什么都写清楚**。②以为结构化就更准确——格式对了内容仍可能是错的 |

**追问句：**
```text
请严格按以下结构输出，不要添加任何额外说明文字：

字段：
- 名称（字符串，必填）
- 数值（数字，必填；无法确定填 null，不要猜）
- 来源（字符串，必填；没有来源填 "未找到"）
- 置信（high / medium / low 三者之一）

要求：字段名不得改动；不确定的一律填 null 或 "未找到"，不要编造。
```

## 6. 沙箱与权限（Sandbox / Permissions）

| | |
|---|---|
| 💬 **一句人话** | 给 AI 划定的**活动范围**：能碰哪些目录、能不能联网、要不要每步问你 |
| ⏰ **什么时候有用** | 让 AI 动真实文件、真实账号、真实钱的时候 |
| ⚠️ **最容易误解** | ①以为"全自动"总是更好——**放开审批意味着错误也自动执行**。②以为它会自己判断危险操作 |

**追问句：**
```text
开始之前，先列出你打算执行的所有操作，标注哪些不可逆
（删除、覆盖、提交、发送、付款）。
不可逆操作先问我确认，不要直接做。
```

> 💡 **实操**：不可逆的三件事——**删除、覆盖、对外发送**。这三类永远保留人工确认。

## 7. Vibe Coding（凭感觉编程）

| | |
|---|---|
| 💬 **一句人话** | 不懂代码也能靠描述需求让 AI 做出能用的东西 |
| ⏰ **什么时候有用** | 做小工具、原型、一次性脚本、自己用的小网页 |
| ⚠️ **最容易误解** | ①以为能一路做到复杂系统——**改到一定规模就会陷入"改一处坏三处"**。②以为跑起来就等于对——没有测试的"能跑"很脆 |

**追问句：**
```text
如果 GitHub / npm 上有成熟的开源方案，直接复用，不要自己实现。
每完成一小步就停下来，告诉我怎么自己验证这一步是好的，我确认后再继续。
```

> 💡 这句"有成熟方案就复用"是本库里性价比最高的一句话，摘自 [[20-领域/AI/使用技巧/主页]]。

## 📎 C 组速查

| 你想要 | 需要的条件 | 验收动作 |
|---|---|---|
| 文件真的被改 | 工具权限 | 要 diff |
| 命令真的跑了 | 终端权限 | 要实际输出 |
| 记住我的偏好 | 长期记忆或规则文件 | 新开对话验证一次 |
| 格式每次一致 | 结构化输出 + 字段定义 | 连跑三次比对 |
| 不出事故 | 沙箱 + 审批 | 不可逆操作先确认 |
| 接上我的应用 | MCP 或插件 | 先只读试 |
