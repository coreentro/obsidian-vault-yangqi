# 网页与 UI 黑话词典

> 🎯 **怎么用**：先在"你可能会说"里找到最像你那句话的一条，抄走"可直接对 AI 说"，再拿"验收点"检查结果。
> 每条都是：**你的话 → 术语（白话解释） → 可复制的指令 → 怎么算做到**。

---

## 一、"整体感觉不对"类

### 1. "看起来高级 / 有质感 / 不土"

| | |
|---|---|
| 🗣 **你可能会说** | 想要高级感、别太土、看着值钱、大厂感 |
| 📘 **对应术语** | **视觉层级**（谁最显眼谁其次）、**留白**（空的地方也是设计）、**克制的配色**（少而准）、**一致性** |
| 💬 **白话** | "高级"几乎从不来自加东西，而来自**减东西 + 对齐 + 层级明确**。土的常见原因是：颜色太多、字号档位太多、边框阴影乱用、间距忽大忽小 |

**可直接对 AI 说：**
```text
把这个页面改得更克制专业。具体要求：
1. 颜色只保留 1 个主色 + 1 个强调色 + 中性灰阶，删掉其余装饰色；
2. 字号只用 4 档（大标题／小标题／正文／辅助说明），不要更多；
3. 间距用统一的一套数值（如 4 / 8 / 16 / 24 / 40），不要随手写数字；
4. 去掉不承载信息的边框、阴影和渐变；
5. 同类元素严格左对齐。
改完请列出你改了哪几处，以及为什么这样更克制。
```

| ✅ **验收点** | ❌ **常见误区** |
|---|---|
| 数一数：颜色 ≤ 3 组、字号 ≤ 4 档、间距值来自同一套数列 | 以为"高级 = 加深色模式 + 玻璃拟态"，结果更花 |
| 眼睛扫一遍，能立刻说出"最重要的是哪块" | 换了个字体就交差，层级依旧混乱 |

---

### 2. "别这么挤 / 太满了 / 喘不过气"

| | |
|---|---|
| 🗣 **你可能会说** | 挤、满、密、压抑、看着累 |
| 📘 **对应术语** | **间距节奏**、**分组（邻近原则）**、**信息密度**、**行高** |
| 💬 **白话** | 挤的真正原因往往不是"东西多"，而是**该分组的没分开**——所有间距都差不多，眼睛找不到边界 |

**可直接对 AI 说：**
```text
这一版信息量不减，但要改成不挤。请：
1. 把内容重新分成几个语义组，并明确告诉我你分了几组、依据是什么；
2. 组与组之间的间距，至少是组内元素间距的 2 倍；
3. 正文行高设为字号的 1.5–1.7 倍；
4. 单行文字宽度控制在 40–75 个字符（中文约 20–35 字）；
5. 不要删除内容，也不要靠缩小字号来腾空间。
```

| ✅ **验收点** | ❌ **常见误区** |
|---|---|
| 眯眼看（或缩到 25%），能看出几个明显的"块" | 一律加大间距 → 变成松散大白页 |
| 组间距 ≥ 2× 组内间距 | 靠缩字号解决拥挤 → 更难读 |

---

### 3. "像苹果官网那样"

| | |
|---|---|
| 🗣 **你可能会说** | 像苹果／Stripe／Notion 官网、想要那种感觉 |
| 📘 **对应术语** | **大尺度排版**、**单列叙事**、**高质量主视觉**、**滚动叙事**、**极简导航** |
| 💬 **白话** | 那种感觉 = **一屏只讲一件事** + 巨大标题 + 大量留白 + 一张高质量图。它对**图片素材质量**的依赖远大于代码 |

**可直接对 AI 说：**
```text
我想要苹果官网那种叙事感，但我没有高质量摄影素材。
请在这个约束下改：
1. 改成单列结构，一屏只讲一个卖点；
2. 主标题尺寸远大于正文（形成明显对比），一句话讲清价值；
3. 用纯色块／几何图形／大字排版代替摄影图；
4. 导航精简到 3–5 项；
5. 保持大面积留白，不要填满。
先告诉我你会把内容拆成几屏、每屏讲什么，再动手。
```

| ✅ **验收点** | ❌ **常见误区** |
|---|---|
| 每屏能用一句话总结在讲什么 | 只把字调大、图放大，内容仍然一屏塞五个卖点 |
| 没有高质量图时，用排版而不是低质量图撑场 | 塞免费图库图 → 直接掉档 |

## 二、"具体某处不对"类

### 4. "重点不突出 / 不知道先看哪"

| | |
|---|---|
| 🗣 **你可能会说** | 一眼看不到重点、都很显眼、乱 |
| 📘 **对应术语** | **视觉层级**、**对比（大小/粗细/颜色）**、**F 型 / Z 型阅读动线**、**主行动按钮（Primary CTA）** |
| 💬 **白话** | 所有东西都想突出，等于什么都不突出。层级要靠**明显的差距**，不是微调 |

**可直接对 AI 说：**
```text
请给这个页面建立明确的三级视觉层级：
第一级只允许一个元素（我最想让人先看到的是：［填］）；
第二级 2–3 个；其余全部降为第三级。
手段用大小、粗细、颜色、留白，差距要明显，不要靠 1–2px 的微调。
只保留一个主按钮，其余改成次级或文字链接。
改完标注出你判定的一二三级分别是哪些元素。
```

| ✅ **验收点** | ❌ **常见误区** |
|---|---|
| 眯眼看，第一眼落点唯一 | 三个同样醒目的按钮并排 |
| 主按钮全页只有一个 | 用加粗解决一切 |

---

### 5. "滚动的时候要有感觉"

| | |
|---|---|
| 🗣 **你可能会说** | 滑动有点意思、动起来、别太死板 |
| 📘 **对应术语** | **滚动触发动画**、**渐显（fade-in）**、**吸顶（sticky）**、**视差（parallax）**、**减少动效偏好（prefers-reduced-motion）** |
| 💬 **白话** | 好动效的作用是**帮你理解结构**（"我到哪了""这块是新的一段"），不是炫技。差动效让人晕、让页面卡 |

**可直接对 AI 说：**
```text
加入克制的滚动动效，目的是帮助理解结构，不是炫技：
1. 每个区块进入视口时轻微渐显 + 上移（位移 ≤ 20px，时长 200–400ms）；
2. 同一区块内元素依次出现，间隔 ≤ 80ms，不要逐字动画；
3. 导航吸顶并高亮当前所在区块；
4. 元素只在第一次进入时动，回滚不重复播放；
5. 尊重系统"减少动态效果"设置（prefers-reduced-motion），开启时全部关闭。
不要用视差背景和大幅缩放。
```

| ✅ **验收点** | ❌ **常见误区** |
|---|---|
| 快速滚到底，不晕、不卡、不掉帧 | 每个元素都动 → 眼花 |
| 开启系统"减少动态效果"后动画消失 | 动效时长 1s+ → 感觉迟钝 |

---

### 6. "手机上也要正常"

| | |
|---|---|
| 🗣 **你可能会说** | 手机上别乱、要能自适应、别横着滚 |
| 📘 **对应术语** | **响应式布局**、**断点（breakpoint）**、**移动优先**、**安全区域**、**触控目标尺寸** |
| 💬 **白话** | 不是"缩小"，是**重新排**：多列变单列、导航收进菜单、表格能横滑、按钮够大能戳中 |

**可直接对 AI 说：**
```text
按移动优先重做适配，验收基准是 375px 宽：
1. 多列在窄屏合并为单列，调整顺序保证最重要的内容仍在最前；
2. 任何情况下不出现横向滚动（宽表格除外，且需给出明确横滑提示）；
3. 可点区域不小于 44×44px，相邻可点元素间距 ≥ 8px；
4. 导航收进汉堡菜单，展开后可一屏看完；
5. 正文字号不小于 16px（避免 iOS 自动缩放）；
6. 底部固定元素避开手机安全区域。
列出你在 375 / 768 / 1280 三个宽度下分别做了什么变化。
```

| ✅ **验收点** | ❌ **常见误区** |
|---|---|
| 375px 下无横向滚动条 | 只做了等比缩放，字变得极小 |
| 单手拇指能准确点到主按钮 | 按钮挤在一起，误触 |

---

### 7. "字看着不舒服"

| | |
|---|---|
| 🗣 **你可能会说** | 字丑、看着累、密密麻麻 |
| 📘 **对应术语** | **字体家族**、**字号阶梯**、**行高**、**字重对比**、**行长（measure）**、**中英文混排** |
| 💬 **白话** | 中文网页最常见三个毛病：**行高太小**、**一行太长**、**用细字重当正文** |

**可直接对 AI 说：**
```text
只调排版，不改内容与配色：
1. 正文 16–18px，行高 1.6–1.75；
2. 一行控制在 20–35 个汉字；
3. 正文字重不低于 400，不要用 300 当正文；
4. 字号阶梯用固定比例（如 1.25 倍递进），共 4–5 档；
5. 中英文混排时，中文与英文/数字之间留出适当间隙；
6. 标题与其下方正文的间距，小于该标题与上一段的间距（让标题"贴住"它管的内容）。
```

| ✅ **验收点** | ❌ **常见误区** |
|---|---|
| 连读三段不觉得累 | 追求"细字体高级"，正文用 300 字重 |
| 标题明显归属于它下面的段落 | 标题上下间距一样 → 不知它管哪段 |

---

### 8. "颜色搭不好 / 花"

| | |
|---|---|
| 🗣 **你可能会说** | 颜色乱、花、脏、不搭 |
| 📘 **对应术语** | **主色/强调色/中性色**、**60-30-10 比例**、**对比度（WCAG AA）**、**语义色**（成功/警告/危险） |
| 💬 **白话** | 花 = 多个饱和度高的颜色抢地位。稳的做法：**大面积中性灰白，主色只在关键处出现** |

**可直接对 AI 说：**
```text
重做配色，保持现有主色不变：
1. 按 60/30/10 分配：60% 中性底色、30% 次要色、10% 强调色；
2. 主色只用在主按钮、关键链接和当前状态，不要用作大面积背景；
3. 正文与背景对比度至少 4.5:1，大字至少 3:1，并报出实际数值；
4. 成功/警告/危险各只固定一个颜色，不要混用；
5. 灰阶从同一色相派生（略带主色倾向），避免"脏灰"。
输出最终色板：色值 + 用途 + 对比度。
```

| ✅ **验收点** | ❌ **常见误区** |
|---|---|
| 打印成黑白后，层级仍然清楚 | 只靠颜色区分状态（色弱用户看不出） |
| 对比度数值达标（4.5:1 / 3:1） | 大面积用饱和主色 → 刺眼 |

---

### 9. "加载 / 点击的时候没反应"

| | |
|---|---|
| 🗣 **你可能会说** | 点了没反应、不知道好没好、卡住了 |
| 📘 **对应术语** | **状态反馈**、**加载态（loading）/空状态/错误态**、**骨架屏**、**乐观更新**、**禁用态** |
| 💬 **白话** | 一个控件至少要有四种样子：**平时 / 悬停或按下 / 正在处理 / 出错**。少了"正在处理"，用户就会连点 |

**可直接对 AI 说：**
```text
给所有交互补齐状态：
1. 按钮四态：默认、悬停/按下、加载中（禁用+转圈+文案变"提交中…"）、错误；
2. 列表三态：加载中用骨架屏、无数据给空状态（说明+下一步动作）、失败给错误态+重试按钮；
3. 任何超过 300ms 的操作必须有可见反馈；
4. 错误提示写清"发生了什么 + 我该怎么办"，不要只写"操作失败"；
5. 提交中禁用按钮，防止重复提交。
```

| ✅ **验收点** | ❌ **常见误区** |
|---|---|
| 断网点提交，能看到明确错误+重试 | 只做成功路径 |
| 快速连点两次，不会提交两条 | 用弹窗当唯一反馈 |

---

### 10. "改一处别的地方就乱"

| | |
|---|---|
| 🗣 **你可能会说** | 一改就乱、越改越糟、前面改好的又坏了 |
| 📘 **对应术语** | **设计令牌（design tokens）**、**组件化**、**单一数据源**、**样式作用域** |
| 💬 **白话** | 乱的根源是**同一个值被抄了很多份**。改成"变量集中定义、各处引用"，改一次全站生效 |

**可直接对 AI 说：**
```text
把散落的样式收敛成变量与组件：
1. 抽出设计令牌（颜色、字号、间距、圆角、阴影），集中定义在一处；
2. 页面里不再出现硬编码的具体数值，全部引用令牌；
3. 重复出现 3 次以上的结构抽成组件（卡片、按钮、区块标题）；
4. 告诉我哪些地方原先重复定义、你合并成了什么；
5. 不要改变现有视觉效果——这是纯重构，改完外观应基本一致。
```

| ✅ **验收点** | ❌ **常见误区** |
|---|---|
| 改一个变量，全站同步变化 | 一边抽变量一边顺手改设计 → 无法判断哪里出问题 |
| 重构前后截图对比基本一致 | 组件拆得过细，反而更难改 |

## 三、"内容层面不对"类

### 11. "文案说不到点上"

| | |
|---|---|
| 🗣 **你可能会说** | 太虚、都是废话、没说到点 |
| 📘 **对应术语** | **价值主张**、**利益点 vs 功能点**、**首屏三问**、**行动召唤（CTA）** |
| 💬 **白话** | 首屏必须三秒答完三问：**这是什么 / 对谁有用 / 我下一步干什么**。"赋能""一站式""领先"这类词等于没说 |

**可直接对 AI 说：**
```text
重写首屏文案。硬性要求：
1. 主标题一句话说清"给谁解决什么问题"，不超过 20 个字，不用"赋能／一站式／领先／打造"；
2. 副标题一句话说清怎么做到的；
3. 三个卖点全部改成用户得到的结果，不要写功能名称；
4. 主按钮写具体动作（如"免费试听第一节"），不要写"了解更多"；
5. 每条卖点后面标注：如果被质疑，我该用什么证据支撑。
先给我 3 个不同角度的主标题版本，并说明你推荐哪个、为什么。
```

| ✅ **验收点** | ❌ **常见误区** |
|---|---|
| 遮住 logo，仍能看出这是给谁的 | 把功能清单当卖点 |
| 每个卖点都能追问出一条证据 | CTA 写"了解更多" |

---

### 12. "结构乱 / 不知道放哪"

| | |
|---|---|
| 🗣 **你可能会说** | 顺序不对、找不到、逻辑乱 |
| 📘 **对应术语** | **信息架构（IA）**、**卡片分类法**、**导航层级**、**面包屑** |
| 💬 **白话** | 结构要按**用户的任务**排，不是按你的部门或知识体系排 |

**可直接对 AI 说：**
```text
重排信息结构。请先列出这个页面/站点要服务的 3–5 个用户任务，
然后按"完成任务所需的顺序"重排内容，而不是按我们内部的分类。
要求：
1. 一级导航 3–5 项，每项都是用户会用的词（不用内部术语）；
2. 任何内容点击不超过 3 层可达；
3. 给出重排前后的对照表，并说明每处调整的理由；
4. 指出哪些内容应该合并、哪些应该移到二级。
```

| ✅ **验收点** | ❌ **常见误区** |
|---|---|
| 找任一常用信息 ≤ 3 次点击 | 用内部部门名当导航 |
| 导航词是用户会说的话 | 一级导航塞 8 项以上 |

## 📎 速查表

| 你的话 | 真正要改的 | 关键词 |
|---|---|---|
| 高级 / 不土 | 减色、统一字号间距 | 视觉层级、留白、一致性 |
| 挤 | 分组，不是删内容 | 间距节奏、邻近原则 |
| 像苹果官网 | 一屏一件事 | 单列叙事、大尺度排版 |
| 看不到重点 | 只留一个第一级 | 视觉层级、主 CTA |
| 滚动有感觉 | 轻微渐显＋吸顶 | 滚动动效、reduced-motion |
| 手机上正常 | 重排而非缩放 | 响应式、断点、44px |
| 字不舒服 | 行高与行长 | 字号阶梯、行高 1.6 |
| 颜色花 | 主色只用在关键处 | 60-30-10、对比度 |
| 点了没反应 | 补加载/错误态 | 状态反馈、骨架屏 |
| 一改就乱 | 变量集中定义 | 设计令牌、组件化 |
| 文案虚 | 写结果不写功能 | 价值主张、首屏三问 |
| 结构乱 | 按任务排序 | 信息架构、卡片分类 |
